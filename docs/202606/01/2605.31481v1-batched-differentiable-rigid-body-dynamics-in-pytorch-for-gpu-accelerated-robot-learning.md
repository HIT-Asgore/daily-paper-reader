## 摘要
随着机器人控制转向包含循环动力学计算的大规模强化学习，社区对Pinocchio等CPU绑定库的依赖在基于GPU的训练流程中造成了吞吐量瓶颈。我们提出了BARD（批量化铰接式刚体动力学），这是Featherstone刚体动力学算法的自包含PyTorch实现，针对批量化GPU评估和自动微分进行了优化。三个设计选择使其高效：分层惰性求值缓存避免冗余树遍历，通过预计算Rodrigues常数的无矩阵乘法关节变换，以及将顺序操作减少到树深度批处理步骤的层级并行传播。在五个机器人模型（7-23自由度）上，BARD在数值上与Pinocchio匹配，同时在NVIDIA H200上批大小为4096时，正向运动学吞吐量高达64倍，雅可比矩阵高达63倍。我们通过在7自由度机械臂上进行基于梯度的系统辨识来验证可微性，在5%扭矩噪声下恢复连杆质量的平均误差为1.24%，并将BARD集成到Isaac Lab AMP训练流程中，用于具有4096个并行环境的11自由度脊柱四足机器人，其循环动力学比Pinocchio快8.5倍，比ADAM快2.0倍。BARD开源地址：https://github.com/YueWang996/bard-pytorch-dynamics。

## Abstract
As robot control shifts toward large-scale reinforcement learning with in-loop dynamics computation, the community's reliance on CPU-bound libraries such as Pinocchio creates a throughput bottleneck in GPU-based training pipelines. We present BARD (Batched Articulated Rigid-body Dynamics), a self-contained PyTorch implementation of Featherstone's rigid-body dynamics algorithms, optimized for batched GPU evaluation and automatic differentiation. Three design choices make this efficient: a tiered lazy-evaluation cache that avoids redundant tree traversals, matmul-free joint transforms via pre-computed Rodrigues constants, and level-parallel propagation that reduces sequential operations to tree-depth batched steps. On five robot models (7-23 DOFs), BARD matches Pinocchio numerically while reaching up to 64x higher throughput for Forward Kinematics and 63x for Jacobians at batch size 4096 on an NVIDIA H200. We validate differentiability through gradient-based system identification on a 7-DOF manipulator, recovering link masses to 1.24% mean error under 5% torque noise, and integrate BARD into an Isaac Lab AMP training pipeline for an 11-DOF spined quadruped with 4096 parallel environments, where it is 8.5x faster than Pinocchio and 2.0x faster than ADAM for in-loop dynamics. BARD is open-sourced at: https://github.com/YueWang996/bard-pytorch-dynamics.

### 1. 核心问题与整体含义（研究动机与背景）

- **需求**：需要一个能够嵌入 PyTorch 训练循环、支持批处理 GPU 加速、且可微分的动力学库，以提供模块化的动力学算子（如雅可比、质量矩阵）用于梯度反向传播（如系统辨识、物理信息奖励）。
- **贡献**：提出 BARD（Batched Articulated Rigid-body Dynamics），一个完全基于 PyTorch 的开源库，实现 Featherstone 算法家族，针对 GPU 批处理评估和自动微分优化，显著提升大规模机器人学习中的动力学计算吞吐量。

### 2. 方法论：核心思想与关键技术

#### 核心思想
重新组织 Featherstone 的递归树遍历算法，使其适合 GPU 的并行执行模式，并利用 PyTorch 的自动微分和编译优化。

#### 关键技术细节

1. **三级懒求值缓存（Tiered Lazy Evaluation）**  
   - 将运动学状态分为三个层级，每层设置有效标志，仅在首次下游查询时计算：
     - 1 级：局部父子变换（`T_{pc,i}`），由关节角度 `q` 直接生成。
     - 2 级：空间邻接变换（`X_{up,i}`, `X_{up,i}^T`, `S_i`），用于动力学算法（RNEA, CRBA, ABA）。
     - 3 级：世界坐标系位姿（`^0_T_i`），用于正向运动学和雅可比。
   - 避免不必要的全树计算，例如仅调用 RNEA 时不会计算世界坐标系传播。

2. **无矩阵乘法的关节变换**  
   - 旋转关节的父子变换 `T_{pc,i} = T_{joint,i} · R_axis(q_i) · T_{link,i}` 通常需要两次 4×4 矩阵乘法，但可通过预计算常数矩阵，在运行时仅用 `sin(q_i)` 和 `cos(q_i)` 进行元素级运算：
     - 预计算 `R^{(0)}_i`, `A_i`, `B_i`, `t^{(0)}_i`, `a_i`, `b_i`。
     - 运行时：`R_{pc,i} = R^{(0)} + sin(q)A + (1-cos(q))B`，平移类似。
   - 将 $\mathcal{O}(n_b \times B)$ 次小矩阵乘法替换为标量-矩阵乘法，PyTorch 编译器可融合为单一内核启动。

3. **层级并行树传播**  
   - 将树中同一深度的节点归为同一层级（在构建模型时预计算），同一层级内的节点可并行处理，将 $n_b$ 次顺序操作减少为树深度 $d$ 次批处理操作（例如四足机器人从 11 步减为 3 步）。
   - 用于正向速度传播、前向 RNEA、ABA 前向加速度传播。后向传播（力/惯性从叶到根）仍保持逆拓扑顺序，但所有环境同时处理。

4. **直接雅可比列构建**  
   - 避免构造完整的 6×6 伴随矩阵，对于单自由度关节（大多数），利用世界坐标系旋转和平移（已缓存的 FK 结果）直接计算雅可比列：`J_k = [p_{wk} × (R_{wk} * a'_k); R_{wk} * a'_k]`。

5. **内存布局与编译器兼容**  
   - 使用 `(B, n_b, ...)` 批优先布局，存储 `X_{up,i}` 及其转置 `X_{up,i}^T` 的连续副本，避免非连续视图。
   - 对关键 6×6 更新 `Out += X_i^T · M_i · X_i`，提供可选 Triton 融合内核。
   - 使用常量索引张量、无数据依赖分支、无 `.item()` 调用，确保 `torch.compile` 可完整追踪为单一融合图。

### 7. 优点

- **纯 PyTorch 实现**：无缝集成现有基于 PyTorch 的 RL 管线，支持 `torch.compile`，无需切换后端。
- **高吞吐**：通过懒求值、无矩阵变换、层级并行等 GPU 特定优化，大幅超越现有方法。
- **模块化与可微性**：提供独立的 FK、雅可比、RNEA、CRBA、ABA 算子，可嵌入自定义损失函数并自动求导。
- **开源**：代码已发布，便于复现和扩展。
- **全面实验验证**：数值精度、吞吐量扩展、系统辨识、RL 训练——覆盖从单配置到大规模并行训练的多层次需求，跨多 GPU 架构。
- **分析 torch.compile 局限性**：明确指出编译在低端 GPU 上对动力学的退化，提供实用建议。

### 8. 不足与局限

- **未支持接触动力学**：当前仅实现无接触的刚体运动，无法处理接触/碰撞，限制了在完整物理仿真中的应用。
- **小自由度/小批量优势较小**：对于 3-DOF 或批量 64 以下，内核启动开销占比增大，速度提升有限（如 RL 实验 2× 对比 64× 的原因）。
- **torch.compile 退化问题**：在 L4/L40S 等低带宽 GPU 上，编译后的动力学全管线性能甚至低于 Pinocchio 基准，用户需根据硬件和任务选择模式。
- **ADAM 兼容性问题**：G1 机器人未测试，因 ADAM 的 URDF 解析器存在兼容性问题，影响了部分对比公平性。
- **对 GPU 架构敏感**：最佳性能需高端 GPU（H200/H100），在低端 GPU 上收益递减。
- **接触/摩擦缺失**：论文提及未来工作将加入接触动力学，目前尚未实现。
- **实验场景有限**：RL 训练仅展示 SPARC 四足，未在更多机器人或任务上验证；系统辨识仅恢复质量，未测试其他参数（如惯性、摩擦）。
